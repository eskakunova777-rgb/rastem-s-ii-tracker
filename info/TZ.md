# ТЗ: трекер задач «Растем с ИИ · Задачи»

Заказчик: Евгения Скакунова (проект «Растем с ИИ»). Версия ТЗ: 1, 9 октября 2026.
Собрано мозговым штурмом из 20 вопросов (`brainstorm.md`). Брендбук: `brandbook.md`, оформление снято с сайта evskakunova-ai.ru (`site-style.css`), логотип `logo.png`.

## 1. Сообщение клиента

Я делаю под ключ системы «маркетинг, контент, продажи» на ИИ. Мой проект «Растем с ИИ» это продвижение моих услуг на российском и зарубежном рынке (соцсети и сайт) и поиск заказов на маркетплейсах в России и за рубежом. Задачи разбросаны: часть в чатах с Claude, часть в Telegram, часть в заметках и файлах проектов. Хвосты теряются: задача может быть давно закрыта, а у меня числится открытой, или наоборот. Мой ассистент это ИИ: он делает работу, я проверяю, но сейчас не видно, что он сдал и что ждёт моей проверки. Нужно одно место, где видны все задачи по направлениям, кто делает, срок, результат и почему что-то просрочено.

Ниша: малый бизнес (услуги автоматизации и продвижения). Тип трекера: задачи.

## 2. Цель

Одно место для всех задач проекта «Растем с ИИ»: владелец ставит и проверяет, ИИ-ассистент выполняет и сдаёт на проверку через API, просрочки видны с причинами.

## 3. Роли и права

| Действие | Владелец (админ) | Ассистент (ИИ) |
|---|---|---|
| Видеть задачи | все | все |
| Создавать задачи | да | нет, только предлагать (статус «Предложена»), не больше 5 непринятых одновременно |
| Принимать или отклонять предложения | да | нет |
| Редактировать задачу | любую | только свою: статус, комментарий, результат, причина просрочки |
| Менять статус | любой | Новая → В работе → На проверке; в «Готово» нельзя |
| Вернуть из «На проверке» в работу | да, с обязательным комментарием | нет |
| Удалять задачи | да | нет |
| Пользователи, категории, ключ API, выгрузка CSV | да | нет |

## 4. Авторизация и управление пользователями

- Вход по логину и паролю, пароль хранится только как хеш (scrypt с солью, встроен в Node.js).
- 5 неверных попыток: блок входа на 15 минут.
- Сессия 30 дней, cookie `httpOnly`, `secure` на https.
- Регистрации нет: аккаунты создаёт владелец в «Настройках».
- Смена пароля в профиле для каждого пользователя.
- Ассистент работает через API по ключу (заголовок `Authorization: Bearer <ключ>`); ключ перевыпускается кнопкой в настройках, хранится как хеш.
- Ассистент может войти и в интерфейс под своим аккаунтом (для проверки прав).
- Двухфакторная защита: следующий этап.

## 5. Данные

**Задача:** название; описание; категория; исполнитель (владелец или ассистент); срок; приоритет (низкий, средний, высокий); статус (Предложена, Новая, В работе, На проверке, Готово); результат (ссылка и/или файл до 20 МБ); причина просрочки (список + комментарий); кто создал, когда.

**Категории (редактируются владельцем):** Соцсети РФ, Соцсети зарубеж, Сайт, Маркетплейсы РФ, Маркетплейсы зарубеж.

**Причины просрочки:** ждёт моего решения или проверки; ждёт ответа клиента или площадки; не хватило доступа или данных; переоценили объём; сменился приоритет; другое (+ комментарий).

**История:** комментарии и изменения (статус, срок, исполнитель, результат: кто, когда, было, стало) одной лентой по времени.

## 6. Экраны и функции

1. **Вход.** Логотип, «Растем с ИИ · Задачи», логин, пароль.
2. **Доска.** Канбан: узкая колонка «Предложена» (с кнопками Принять / Отклонить), затем Новая, В работе, На проверке, Готово. Фильтры: категория, исполнитель, «просрочено». Бейдж «На проверке: N» в шапке. Просроченная задача подсвечена кораллом, «Готово» зелёной отметкой.
3. **Карточка задачи.** Все поля, результат (ссылка, файл), причина просрочки (обязательна, если срок прошёл и задача не в «Готово»), лента истории и комментариев, кнопка «Повторить задачу» (копия со сроком +7 дней).
4. **Мои задачи.** Список задач текущего пользователя: просроченные, на сегодня, дальше.
5. **Сводка.** По каждой категории: в работе, на проверке, просрочено; разбивка просрочек по причинам.
6. **Настройки** (владелец). Пользователи, категории, ключ API ассистента (перевыпуск), выгрузка задач в CSV, «занято файлами: N МБ».
7. **Профиль.** Имя, смена пароля.

## 7. API ассистента

| Метод | Что делает |
|---|---|
| `GET /api/tasks?mine=1` | мои задачи (фильтр по статусу) |
| `GET /api/tasks/:id` | задача с историей |
| `PATCH /api/tasks/:id` | статус (не «Готово»), причина просрочки |
| `POST /api/tasks/:id/comments` | комментарий |
| `POST /api/tasks/:id/result` | результат: ссылка или файл до 20 МБ |
| `POST /api/proposals` | предложить задачу (лимит 5 непринятых, иначе 429) |

Нейросеть через платный API не вызывается: работу выполняет Claude Code в рамках подписки и обращается к API трекера по ключу.

## 9. Адаптивность

- Основное: компьютер (Mac).
- Телефон: доска в одну колонку со вкладками статусов; карточку можно открыть, проверить и перевести в «Готово».
- Планшет отдельно не делается.

## 10. Хранение, копии, публикация

- База SQLite + папка файлов, всё в одном томе Docker.
- Ночная копия базы (храним 14), файлы одной зеркальной копией.
- Публикация: свой VPS (Docker + Traefik), адрес `https://tracker.evskakunova-ai.ru`, A-запись в Бегете добавляет владелец. Railway не используется (честная замена: свой сервер уже оплачен и обслуживается).
- Код в приватном репозитории GitHub.
- При запуске загружаются 10-15 реальных задач, одобренных владельцем.

## 11. Критерии готовности MVP

1. Владелец и ассистент входят под своими аккаунтами; запреты ассистента (Готово, удаление, настройки) проверены тестом.
2. Задача создаётся, редактируется, проходит все статусы; результат ссылкой или файлом до 20 МБ.
3. Ассистент через API получает свои задачи, меняет статус, комментирует, прикладывает результат, предлагает задачу; лимит 5 работает.
4. Просроченная задача подсвечена и требует причину; сводка считает просрочки по категориям и причинам.
5. Доска на телефоне работает в одну колонку.
6. Трекер открывается по `https://tracker.evskakunova-ai.ru` без порта, данные переживают перезапуск, ночная копия создана.
7. Загружены 10-15 реальных задач, одобренных владельцем.

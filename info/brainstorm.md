# Мозговой штурм для ТЗ (в Claude, 20 вопросов по одному)

Промпт: «У меня есть сообщение от клиента: [текст]. Задай мне вопросы по очереди, чтобы сформировать техническое задание для создания этого приложения» + брендбук (brandbook.md, brandbook-card.png).

1. В: Какие проекты будут в трекере с первого дня?
   О: Проект «Растем с ИИ». Включает комплексное продвижение услуг на российском и зарубежном рынке (соцсети + сайт) и поиск заказов на маркетплейсах в России и за рубежом.

2. В: На какие направления делим задачи внутри проекта: сетка «рынок × канал» или один список категорий?
   О: Одним списком: «Соцсети РФ», «Соцсети зарубеж», «Сайт», «Маркетплейсы РФ», «Маркетплейсы зарубеж».

3. В: Какие статусы проходит задача? (предложено: Новая → В работе → На проверке → Готово)
   О: Ассистент у нас ИИ: он делает, я проверяю. Статусы подходят: ассистент доводит до «На проверке», в «Готово» переводит только владелец.

4. В: Как ИИ-ассистент работает с трекером: сам через API или вручную через владельца?
   О: Вариант А (сам, через API трекера), но бесплатно, без платного API нейросети. Решение: API трекера наш собственный (бесплатный, на своём сервере); работу делает Claude Code в рамках уже оплаченной подписки и обращается к трекеру по ключу ассистента.

5. В: Какие поля нужны у задачи? (предложено: название, описание, категория, исполнитель, срок, приоритет, статус, комментарии)
   О: Всё предложенное плюс результат: ссылка (пост, страница, объявление на маркетплейсе) или файл с результатом.

6. В: Какие файлы будут результатом и какого размера?
   О: Согласна с предложением: файлы до 20 МБ (картинки, карусели, PDF, тексты) грузим в трекер, тяжёлое видео прикладываем ссылкой на Яндекс.Диск.

7. В: Какие экраны нужны? (предложено: вход, доска-канбан с фильтрами, карточка задачи, «мои задачи», настройки и профиль)
   О: Всё предложенное плюс экран сводки: сколько задач в работе и просрочено по каждой категории, с причинами просрочки.

8. В: Кто и когда указывает причину просрочки?
   О: Как предложено: после срока задачи (не в «Готово») появляется обязательное поле «Причина просрочки», задача подсвечена красным, пока не заполнено. Список: ждёт моего решения/проверки; ждёт ответа клиента или площадки; не хватило доступа или данных; переоценили объём; сменился приоритет; другое (+ комментарий). Ассистент заполняет через API для своих задач, владелец для своих.

9. В: Нужны ли уведомления (Telegram: задача на проверке, просрочка, утренняя сводка)?
   О: Вариант В: в MVP без уведомлений, выносим в следующий этап и в допродажи.

10. В: На каких устройствах открывается трекер?
    О: Основное: Мак (desktop). На телефоне доска в одну колонку со вкладками статусов, карточку можно проверить и перевести в «Готово». Планшет отдельно не делаем.

11. В: На каком адресе будет трекер?
    О: tracker.evskakunova-ai.ru (свой VPS, раздача через Traefik).

12. В: Как защищаем вход?
    О: Как предложено: логин и пароль (хеш в базе), блок на 15 минут после 5 неверных попыток, сессия 30 дней, регистрации нет (аккаунты создаёт владелец), ключ API ассистента перевыпускается кнопкой. Двухфакторная защита в следующий этап.

13. В: Что может делать ассистент, а что нет?
    О: Права приняты: админ может всё; ассистент видит все задачи, меняет статус только до «На проверке», не редактирует чужие и не удаляет, комментирует и прикладывает результат, в настройки доступа нет. Возврат из «На проверке» в «В работе» только с комментарием.
    Уточнение владельца: «А не получится, что ассистент насоздаёт себе лишних задач?» Решение: ассистент не создаёт задачи, а предлагает (статус «Предложена», отдельная колонка, не идёт в работу и в сводку); владелец принимает или отклоняет; лимит 5 непринятых предложений, дальше API отказывает.

14. В: Нужна ли история изменений задачи?
    О: Да: лента внизу карточки, комментарии и изменения (статус, срок, исполнитель, кто и когда) вместе по времени.

15. В: Повторяющиеся задачи: кнопка «Повторить» или полноценное расписание?
    О: Вариант А: в MVP кнопка «Повторить задачу» (копия со сроком +7 дней). Расписание в следующий этап.

16. В: Переносим ли существующие задачи в трекер при запуске?
    О: Вариант Б: заносим 10-15 реальных задач по пяти категориям (список собирает агент из реальных файлов проектов, владелец утверждает перед загрузкой).

17. В: Резервные копии: где и как часто?
    Уточнение владельца: «Место на сервере есть?» Проверено: диск 40 ГБ, свободно 23 ГБ (занято 41%).
    О: Каждую ночь копия базы (храним 14), файлы результатов одной зеркальной копией с добавлением новых. В настройках счётчик «занято файлами», при 5 ГБ старые результаты переносим на Яндекс.Диск ссылкой. Кнопка выгрузки задач в CSV.

18. В: Как оформить по брендбуку (цвета, шрифты, логотип, тёмная тема, название в шапке)?
    О: «Бери с сайта evskakunova-ai.ru». Снято с живого сайта (info/site-style.css): светлая тёплая тема без тёмной; фон #faf6ef, мягкий фон #f3ede1, карточки белые, рамки #e8dfd0, акцент #0a7089 (#086476, градиент #0d7e93→#075a68), мягкий акцент #e6f3f5, текст #241f2b, приглушённый #6f7d80; системный шрифт -apple-system; карточки со скруглением 18px, кнопки-«таблетки» с градиентом; в шапке знак EC высотой 46px + «Евгения Скакунова». Для трекера: шапка как на сайте + метка «Растем с ИИ · Задачи». Коралл и зелёный из брендбука только для просрочки и «Готово».

19. В: Что считаем готовым MVP?
    О: Принято 7 критериев: (1) два аккаунта, запреты ассистента проверены тестом; (2) задача создаётся, редактируется, проходит все статусы, результат ссылкой или файлом до 20 МБ; (3) API ассистента: свои задачи, статус, комментарий, результат, предложение, лимит 5; (4) просрочка подсвечена, причина обязательна, сводка по категориям и причинам; (5) доска на телефоне в одну колонку; (6) https://tracker.evskakunova-ai.ru без порта, данные переживают перезапуск, ночная копия создана; (7) загружены 10-15 реальных задач, одобренных владельцем.

20. В: Сроки и порядок работ; кто добавляет DNS-запись?
    О: Порядок принят: сегодня ТЗ и MVP локально, затем роли, API, просрочки, сводка, тестирование, оформление, затем публикация на VPS. A-запись tracker.evskakunova-ai.ru в Бегете добавляет владелец. Проект нужно выложить на GitHub.

Уточнение владельца после штурма (10 октября): адрес меняем на tracker.evskakunova-ai.ru. Причина: evskakunova.ru это портфолио творческих работ, а автоматизация и проект для экспертов живут на evskakunova-ai.ru.

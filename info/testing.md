# Протокол тестирования трекера

## Итерация 1: MVP после первого запуска (9 октября 2026)

Проверено в браузере (Playwright, 1280×800 и 375×812) и запросами к API под двумя аккаунтами.

**Работает:** вход и выход; доска из 4 колонок; создание задачи с категорией, исполнителем, сроком; редактирование и смена статуса; комментарии; история изменений; текст вида `<img src=x onerror=alert(1)>` выводится как текст, скрипт не срабатывает.

## Проверка безопасности

| Риск | Что сделано | Проверка |
|---|---|---|
| Пароли в базе | хеш scrypt с солью, сравнение за постоянное время | код `db.js` |
| Подбор пароля | блок на 15 минут после 5 ошибок | автотест 4 |
| Кража сессии | cookie `HttpOnly`, `SameSite=Lax`, `Secure` на https; в базе хранится хеш токена | автотест «заголовки и cookie» |
| Ключ API | 48 случайных символов, в базе хеш, показывается один раз, перевыпуск | автотест 9 |
| SQL-инъекции | все запросы с параметрами, имена полей только из белого списка | автотест «SQL-инъекция» |
| XSS (вредный код в задаче) | интерфейс выводит текст через `textContent`, CSP запрещает чужие скрипты | браузер: `<img src=x onerror=alert(1)>` показан текстом |
| Опасные ссылки | в результате принимаются только `http(s)://` | автотест 8 |
| Формулы в CSV | ячейки, начинающиеся с `= + - @`, экранируются | автотест 12 |
| Встраивание в чужой сайт | `X-Frame-Options: DENY`, `frame-ancestors 'none'` | автотест «заголовки» |
| Загруженные файлы | случайные имена на диске, отдаются только после входа и как вложение | автотест 8 |
| Права ассистента | проверяются на сервере, а не только скрытием кнопок | автотесты 1-3, 6, 9 |

Не сделано (следующий этап): двухфакторная защита; журнал входов; ограничение частоты запросов к API ассистента.

## Оформление по бренду (этап 4)

Промпт: «Оформи трекер по брендбуку компании и добавь логотип. Брендбук лежит в папке `info` (`brandbook.md`, `brandbook-card.png`), оформление брать с сайта evskakunova-ai.ru (`info/site-style.css`). Логотип: `info/logo.png`».

Применено: фон айвори `#faf6ef`, карточки белые со скруглением 18px и рамкой `#e8dfd0`, акцент `#0a7089` и градиент кнопок `#0d7e93 → #075a68`, мягкий акцент `#e6f3f5` для меток и активной вкладки, текст `#241f2b` и `#6f7d80`, системный шрифт как на сайте, знак EC в шапке и на входе, метка «Растем с ИИ · Задачи», коралл только для просрочки, зелёная галочка только для «Готово». После правок приложение перезапущено и открыто заново (чистая загрузка без кэша).

Точечные правки после применения брендбука:
1. У логотипа свой айвори-фон с внутренним прямоугольником: на белой карточке входа был виден квадрат. Сделана копия знака с прозрачным фоном и обрезкой полей (`public/logo.png`), оригинал в `info/` не тронут.
2. На ширине 1280 px кнопка «Выйти» переносилась на вторую строку шапки: метка «Растем с ИИ · Задачи» скрывается на экранах уже 1360 px (она есть на входе и в названии вкладки).
3. На телефоне шапка занимала две строки: кнопки шапки уменьшены, бейдж «На проверке» скрыт (на телефоне его дублирует вкладка статусов), фильтры растянуты на ширину.

## Доработка после публикации (10 октября)

По просьбе владельца добавлен перенос карточек мышкой между колонками (на компьютере). Правила те же, что в карточке: проверяет сервер. Возврат с «На проверке» в «В работе» спрашивает комментарий; просроченная задача без причины открывает карточку с сообщением; предложения мышкой не двигаются. Проверено в браузере: перенос «Новая → В работе» записан в историю, возврат с проверки сохранил комментарий. Также добавлен клиент ассистента `assistant.js` (ключ берётся из окружения): через него на рабочий сервер загружены 10 реальных задач двумя порциями, лимит в 5 предложений сработал на шестой.
